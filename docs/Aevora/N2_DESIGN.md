# N2 Native Guest Memory Design

Status: Stage 3a design note, 2026-10-22. This document records verified observations and the staged plan for replacing the supported-path kernel memory manager with a native guest mapper.

## Purpose

N2 will provide a title-specific guest address space without the emulated kernel memory manager. The native mapper must preserve the fastmem layout expected by generated code while implementing only the memory operations observed on the confirmed N0 gameplay path.

## Scope and non-goals

The scope is the supported path's memory SVCs, guest code/heap/stack/TLS/shared-memory mappings, query and protection behavior, IPC map-alias buffers, and the consumers that must move with them. N2 does not replace threads, synchronization, services, storage, GPU command processing, or the general kernel; those belong to later milestones. GPU/rasterizer cache tracking remains on `Common::PageTable` and `Core::DeviceMemory`, not `KPageTable`.

## Observed

- The N0-observed memory SVCs—0x01 SetHeapSize (1), 0x03 SetMemoryAttribute (137), 0x04 MapMemory (32), 0x05 UnmapMemory (12), 0x06 QueryMemory (266), 0x13 MapSharedMemory (2), 0x15 CreateTransferMemory (119), 0x29 GetInfo (35), 0x2C MapPhysicalMemory (868), and 0x2D UnmapPhysicalMemory (1)—enter `src/core/hle/kernel/svc/svc_memory.cpp`, `svc_physical_memory.cpp`, `svc_query_memory.cpp`, `svc_shared_memory.cpp`, `svc_transfer_memory.cpp`, and `svc_info.cpp`, then reach `KProcessPageTable` (`src/core/hle/kernel/k_process_page_table.h`) and its `KPageTable`/`KPageTableBase` implementation (`src/core/hle/kernel/k_page_table_base.cpp`, about 5,800 lines).
- Other memory-manager users are `KThreadLocalPage` (`k_thread_local_page.cpp`), `KSharedMemory`, `KTransferMemory`, `KCodeMemory`, IPC buffer setup/cleanup in `k_server_session.cpp`, process creation in `k_process.cpp`, `KernelCore` initialization in `kernel.cpp`, nvdrv (`nvmap.cpp`, `core/container.cpp`), `vi/shared_buffer_manager.cpp`, `ro/ro_nro_utils.cpp`, `arm/debug.cpp`, `memory/cheat_engine.cpp`, `debugger/gdbstub.cpp`, and `service/jit/jit_code_memory.cpp`.
- The structural gate's `kernel_memory` deny list (`tools/structural_gate/structural_gate.py`, milestones N2 and N9) matches `KPageTable`, `KMemoryManager`, and `KMemoryBlockManager`; the JIT launcher baseline matched 120 symbols.
- No standalone test currently covers an SVC/KPageTable replacement for map, unmap, protection, or shared memory. Existing standalone memory tests are `src/tests/common/host_memory.cpp`, `tests/recompiler_fastmem`, and `tests/recompiler_smoke/gg_host.cpp`.
- Stage 0 added an opt-in `[memory]` recorder to `src/core/boundary_inventory.h` and the kernel hook sites listed in [CODEBASE_INDEX.md](CODEBASE_INDEX.md). With `SUYU_BOUNDARY_INVENTORY=1`, it records SVC shapes, IPC map-alias descriptors, TLS pages, shared-memory permissions and sizes, and process layout ranges; with the option off it is execution-neutral.

## Inferred / to be verified

- The `KProcessPageTable` to native-mapper object seam is high confidence because the SVC forwarding path is concentrated there; the Stage 1 mapper is a standalone object with no ownership seam yet.
- The `KProcess::Initialize`/`LoadFromMetadata` to address-space allocator seam is medium-high confidence; the exact layout must be fixed from the user's Stage 0 collection.
- The native mapper's core is a physical-memory-backed alias-region allocator plus stack remapping, TLS, shared memory, and transfer-memory locking (inference); the supported path does not reach `SetupForIpc`/`CleanupForIpc*`.
- Region bases are randomized per process creation (inference); Stage 2 must take bases from `KPageTable`'s result, while native-only mode needs one published, consistent base definition.
- The default `DeviceMemory` backing is 4 GiB (`memory_layout_mode` 4/6/8/10/12 GiB), so one 3.01 GiB `MapPhysicalMemory` call fits raw capacity; user-pool availability still needs runtime validation.
- `KernelCore::InitializeMemoryLayout` and slab heaps are medium confidence: kernel initialization is still needed by objects that remain until N3/N4, so bypass timing must be verified rather than assumed.
- The supported-path scope of each consumer listed above, and the behavior of physical addresses as `DeviceMemory` offsets, remains to be verified.

## Seams and FM1 contract

The current seam confidence is: SVC to `KProcessPageTable` high; `KProcessPageTable` to a native mapper object high; `Core::Memory` to `Common::PageTable`/`HostMemory` high; `KProcess::Initialize`/`LoadFromMetadata` to the address-space allocator medium-high; IPC session mapping medium; `KernelCore::InitializeMemoryLayout`/slab heaps medium; and GPU tracking only through `Common::PageTable` high.

A native mapper must keep the FM1 fastmem contract:

- `Common::PageTable` entries remain 32 bytes (`ptr`, `block`, `addr`, `recomp_watch`) with two attribute bits.
- Address-space width remains the NPDM-selected 39, 36, or 32 bits, with code bases `0x80000000`, `0x08000000`, or `0x00200000`.
- `fastmem_arena` is set in `Core::Memory::SetCurrentPageTable` (`src/core/memory.cpp:48-60`).
- Map, unmap, and protection continue through `Core::Memory::MapMemoryRegion`, `UnmapRegion`, `ProtectRegion`, and `HostMemory`.
- The GG1 page-table-swap notification remains intact, and the layout checks and handshake in `src/core/arm/recomp/arm_recomp.cpp` continue to pass.
- Region bases are process-specific observations, not a fixed contract: shadow mode must consume the `KPageTable` result, and native-only mode must publish bases from one consistent definition.

The address layout is exactly the same as `KPageTable`'s layout so that `SUYU_NATIVE_MEM_SHADOW=1` can compare the native mapper with the existing implementation.

## Stage 3 plan

Stage 3 is split into three sub-stages:

- **3a — standalone backing and host mapping:** completed in `v0.0.3-dev7` by adding `MappedAddressSpace` with injected `PhysicalPageSource` and `HostMemoryMap`, and extending `AddressSpace` with the required permission, IO, transfer-lock, device-lock, and mutation-free validation APIs. It remains unconnected to the kernel and host.
- **3b — per-process wiring:** wire `KProcessPageTable` to the native mapper behind `SUYU_NATIVE_MEM`, which defaults on and is disabled with `SUYU_NATIVE_MEM=0`. Unsupported operations (`SetupForIpc`/IPC map-alias, `MapCodeMemory`, and unsafe/insecure paths) use counted fail-fast stubs; primary mode wins over shadow mode with a warning.
- **3c — PLA validation:** run JIT and AOT PLA sessions, including bag and quit segments, and compare CPU milliseconds per frame with the option on and off. Save-data backup is required before these sessions.

The caller inventory is: observed — memory SVCs, TLS, shared memory, transfer memory, and `GetInfo` accounting; likely — process stack/code mapping, nvmap device locks, and the vi shared buffer; unobserved — IPC map-alias, `CodeMemory`, and unsafe/insecure paths. Physical page allocation stays on `KMemoryManager` in Stage 3 behind `PhysicalPageSource`; KPageGroup node lists map to `PhysicalExtent` lists.

### Stage 3b plan

The user-approved Stage 3b plan is split into three deliveries:

- **3b-1 (dev8):** add kernel-free native headers only; nothing is connected to the kernel.
- **3b-2 (dev9):** add, but do not switch, adapters for `PhysicalPageSource` over `KMemoryManager`/`KResourceLimit`, `HostMemoryMap` over `Core::Memory`, `KPageGroup` ↔ extent conversion with `Open`/`Close` refcounts, `KMemoryInfo` conversion, and the native mutex. First record a table of every replaced kernel function's side effects (resource reservation, fill value, and cache operations) here in N2_DESIGN. Cover JIT and no-JIT host builds. Done in `v0.0.3-dev9` (uncommitted until the user commits); see Stage 3b-2 results.
- **3b-3 (dev10):** switch `KProcessPageTable` methods to native-or-`KPageTable`, read `SUYU_NATIVE_MEM` at `Initialize`, default it on, and make it exclusive with the Stage 2 shadow (native primary wins with a warning). Unsupported `SetupForIpc`, `MapCodeMemory`, and unsafe/insecure operations fail fast with operation name and address and are counted. Non-39-bit layouts fall back per process to `KPageTable` with a log. Done in `v0.0.3-dev10` (uncommitted until the user commits); see Stage 3b-3 results.

`SUYU_NATIVE_MEM` does not exist in code before dev10; at dev10 it defaults on and `SUYU_NATIVE_MEM=0` disables it. Native and `KPageTable` cannot both hold per-process state, so per-operation staged migration is impossible. `KPageTable` remains only for layout getters, `Contains`/`CanContain`, `GetBlockInfoManager`, and `Common::PageTable` (`m_impl`). IPC message-copy functions (`CopyMemoryFrom*`) are supported for every HLE request through `k_server_session.cpp` `ReceiveRequest` → `HLERequestContext`; only IPC map-alias (`SetupForIpc`) is unobserved.

Stage 3c is the user's PLA validation: JIT and AOT sessions, including bag and quit segments, with unsupported-operation count 0 and CPU ms/frame plus p99 frame interval compared with the option on and off. The user should back up save data before 3c because dev10 is default-on.

## Stage 3a results

`MappedAddressSpace` is a standalone, non-copyable wrapper around `AddressSpace`. Anonymous mappings allocate and free DeviceMemory-offset extents through `PhysicalPageSource` only after mutation-free validation; caller-owned process-code, shared-memory, IO-memory, and TLS extents are never freed. Alias mapping moves host mappings while retaining source pages. Transfer-memory locks, counted device-map locks, physical-address/extent queries, and `Finalize()` are implemented. `Space()` is read-only, and `InconsistencyCount()` detects lost backing; the writer of extra Locked/Uncached bits remains unidentified.

The native-process smoke unit has 11 checks, including a randomized run-map model and fake-source/fake-host double-free/double-map detection. The unit passed with MSVC 14.51; all 28 mutants exited 1 at their intended checks. Existing native-memory and native-shadow units passed after rebuilding against the changed header. The JIT host tree completed 304 build steps with 0 errors and linked both host executables.

Not run: the full `tests/recompiler_smoke/run.py`, a real smoke-test CMake configure, the no-JIT tree build, and any PLA session. Stage 3a does not yet connect nvmap device-map locks or shared/transfer/vi/TLS callers.

## Stage 3b-2 results

Adapters are in `k_native_memory_adapters.h` (kernel-dependent, compiled into the host through `k_process_page_table.h`, unused) and `native_kernel_convert.h` (kernel-free, unit-tested). Kernel-result raw codes and the state, permission, and attribute encodings are `static_assert`ed against the kernel constants, so a drift breaks the host build. The per-operation rule (`Run`) bounds native physical memory by the process `KResourceLimit` headroom and settles the reservation after the operation; the reservation is atomic inside the page source, so a lost race fails the operation with LimitReached and rolls back. Lock order: the native `KLightLock` (not a `std::mutex`, which would block a host thread across a guest fiber switch) is outermost, then `KMemoryManager` pool locks, then the `KResourceLimit` lock; kernel code never calls back into it. The Codex review of dev9 found 2 P1, 3 P2, 1 P3 (reservation after allocation, std::mutex across fiber switches, double accounting at teardown, skipped fill with optimized allocation, a test that duplicated the algorithm, a bytes/pages comment); all were fixed and the real decorator is now tested.

`native_kernel_convert_unit` passed with nine groups; all 12 header mutants exited 1 at their intended groups. `native_process_memory_unit` still passed. The JIT host tree (304 steps, 0 errors) built and linked `suyu.exe` and `suyu-cmd.exe`. The no-JIT tree (`msvc-release-nojit`, reconfigured, 298 steps in the final incremental build, 0 errors) also linked both executables. Not run: full `run.py`, a real smoke CMake configure, any PLA session. Nothing calls the adapters; `SUYU_NATIVE_MEM` still does not exist in code before dev10.

## Stage 3b-3 results

`KProcessPageTable` now uses the native guest-memory model as the primary page table for 39-bit address spaces. `SUYU_NATIVE_MEM` is read during `Initialize` and defaults on; `SUYU_NATIVE_MEM=0` selects `KPageTable`. Non-39-bit address spaces fall back per process with a log. If `SUYU_NATIVE_MEM_SHADOW=1` is also set, native mode wins and logs a warning. `KPageTable` retains only layout getters, `Contains`/`CanContain`, `GetBlockInfoManager`, and the `Common::PageTable` implementation.

Supported native operations are `SetMemoryPermission`, `SetProcessMemoryPermission` (including JIT instruction-cache invalidation for `ReadExecute`), `SetMemoryAttribute`, `SetHeapSize`, `SetMaxHeapSize`, `QueryInfo`, `MapMemory`/`UnmapMemory`, `MapPhysicalMemory`/`UnmapPhysicalMemory`, the supported `MapPages`/`UnmapPages` cases (fixed Code/CodeData/Stack, anywhere, and caller-owned TLS pages), Shared/IoMemory `MapPageGroup`/`UnmapPageGroup`, transfer-memory and device-address-space locks, all five IPC copy functions, `GetNormalMemorySize`, and `GetCodeSize`/`GetCodeDataSize` (alias sizes are zero). Heap and physical mapping are resource-limit accounted; other mappings are not.

Unsupported operations return `ResultNotImplemented`, increment a per-process counter, and log the operation and address at error level. This includes `MapCodeMemory`, `UnmapCodeMemory`, `MapIo`, `MapIoRegion`, `UnmapIoRegion`, `MapStatic`, `MapRegion`, insecure/unsafe map and unmap operations, `UnmapProcessMemory`, `SetupForIpc`, `CleanupForIpcServer`/`CleanupForIpcClient`, `MakeAndOpenPageGroup`, `InvalidateProcessDataCache`, `ReadDebug*`/`WriteDebug*`, `LockForUnmapDeviceAddressSpace`, `UnlockForDeviceAddressSpacePartialMap`, `OpenMemoryRangeFor*`, `LockForIpcUserBuffer`/`UnlockForIpcUserBuffer`, `LockForCodeMemory`/`UnlockForCodeMemory`, `QueryPhysicalAddress`, `QueryStaticMapping`, `QueryIoMapping`, unsupported page-group states, and unsupported `MapPages` variants. Finalization logs `native_mem final unsupported_ops=N inconsistency=M`; 3c acceptance requires `unsupported_ops=0` in a PLA session.

Documented divergences are that native `MapMemory` unmaps the source host mapping although the kernel leaves it readable; shared, IO, transfer, and TLS external mappings take no extra page reference and therefore depend on their owning object's lifetime; native always fills new pages with heap fill value 0 even in optimized-process mode; and TLS/stack virtual addresses use first-fit placement rather than randomization.

## Stage 2 results

Stage 2 adds an opt-in shadow comparison of the native mapper against `KPageTable` through `SUYU_NATIVE_MEM_SHADOW=1` (off unless exactly `1`, read when the process page table initializes). `Core::NativeMemory::Shadow` owns an `AddressSpace`, mutex, one atomic `m_shadow_state` (high 32 bits are entries, low 32 bits are calls in flight), per-operation counters for `compared`, `result_mismatch`, `state_mismatch`, `boundary_only`, and `skipped`, synchronization-failure tracking, a bounded 32-entry pending-report list, and `Summary()`. A call that is not alone, or whose entry counter changed, is counted as `skipped` and not compared. The seven shadowed operations are `MapMemory`, `UnmapMemory`, `SetMemoryPermission`, `SetMemoryAttribute`, `SetHeapSize`, `MapPhysicalMemory`, and `UnmapPhysicalMemory`; `SetMaxHeapSize` is mirrored as part of heap handling.

The glue observes the complete real block table and `GetNormalMemorySize()` before the real operation, observes touched ranges afterward, then re-adopts the pre-operation table and runs the same operation under the shadow mutex. `ShadowBystander` RAII guards cover 32 reviewed unhooked wrappers that mutate the block table, with two extra source-table guards in `SetupForIpc` and `UnmapProcessMemory`; 15 read-only wrappers have no guard. No lock is held across kernel calls. `AddressSpace::ReplaceBlocks` preserves observed boundaries when they tile the address space and derives the heap end from the leading Normal run; walks stop at the address-space end or a non-advancing block, and request ends saturate. Kernel result codes outside the modeled set map to `Result::Other`.

The shadow physical capacity is a 4 GiB constant. If the real call returns `LimitReached`, capacity is set to the pre-call normal bytes for that operation and restored with `SetPhysicalCapacityBytes`, so that case agrees trivially. For `MapPhysicalMemory` and `UnmapPhysicalMemory`, only `state` is compared on pages mapped before the call and still non-Free afterward; newly mapped pages and freed pages receive a full comparison. The comparison is split at pre-call block boundaries so a merged block cannot hide a new page.

Kernel logs are `native_mem_shadow enabled`; warning lines `native_mem_shadow mismatch: <Op> addr=0x.. size=0x.. <detail>`; periodic summaries `native_mem_shadow compared/result/state/boundary/skipped: sync_failures=N <Op>=compared/result/state/boundary/skipped ...` every 64 compared operations; and `native_mem_shadow final ...` at `Finalize`. Result-class differences, state/permission/attribute differences, and non-tiling synchronization failures are mismatches. Differences only in block base/size, such as merge boundaries or disable-merge heads, are `boundary_only` and are not mismatches. Dev6 removed the temporary 24-entry event ring and before/pre/after block dumps; `LogShadowReports` now runs inside the single shadow-mutex block. If writer hunting resumes, those diagnostics must be re-added.
